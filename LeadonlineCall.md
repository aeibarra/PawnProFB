So, for your call tomorrow
You're not a store using someone's POS — you are the software vendor (PawnPro). Ask them specifically:

"I develop the pawn POS software (PawnPro) my store uses. Do you offer a real-time API for submitting pawn transactions — and is it REST/JSON or still the SOAP web service?"
"How do I get API credentials and the developer/integration documentation for my own software?"
"Does the API also do real-time customer/ID validation at point of sale?" (That's a capability the CSV/FTP flow can't give you — could be worth it.)
Contacts: support@leadsonline.com is the one the API-credentials process points to; general store support is storesupport@leadsonline.com / (800) 311-2656.

Bottom line: a programmatic transaction API definitely exists and is actively used by other POS vendors — so this is a real path off CSV/FTP for you. Whether it's REST specifically is the one thing only they can confirm, and they'll give you the spec once you ask as a software integrator.
